# Phase 5: Token Schema

All token files under `brand/tokens/` share one schema so tools and agents can read them uniformly. It's compatible in spirit with the W3C Design Tokens format (`$value`, `$type`, `$description`) plus provenance fields.

## File envelope

```json
{
  "$schema": "brand-extractor/tokens@1",
  "category": "color",
  "generated": "2026-01-01",
  "project": "<project name>",
  "themes": ["light", "dark"],
  "tokens": {
    "<token-name>": { ...token }
  },
  "recommended": {
    "<token-name>": { ...token, "status": "recommended" }
  },
  "inconsistencies": [
    { "value": "#1a1a1b", "locations": ["src/components/Old.tsx:14"], "note": "Near-duplicate of neutral-950; appears once" }
  ]
}
```

- `tokens` holds **only Observed or Inferred** values.
- `recommended` holds proposals. Never merge the two.
- `inconsistencies` is optional; include when found.

## Token object

```json
{
  "$value": "#0A84FF",
  "$type": "color",
  "$description": "Primary accent for CTAs and active states",
  "status": "observed",
  "source": ["src/app/globals.css:12 --accent", "tailwind.config.ts:22 colors.accent"],
  "role": "accent",
  "tier": "core",
  "usage": "Primary buttons, links, focus rings",
  "original": "hsl(211 100% 52%)",
  "rgb": "10 132 255",
  "themes": { "dark": "#409CFF" }
}
```

Required: `$value`, `$type`, `$description`, `status` (`observed` | `inferred` | `recommended`), `source` (array; may be empty only for `recommended`).

Optional per category:

| Category / file | `$type` | Extra fields |
|---|---|---|
| `colors.json` | `color` | `role`, `tier` (core/supporting/functional/decorative), `usage`, `original`, `rgb`, `themes`, `contrast` (`{ "on": "<token>", "ratio": 7.2, "level": "AAA" }`) |
| `typography.json` | `typography` (composite) or `fontFamily` / `fontWeight` / `dimension` | composite `$value`: `{ fontFamily, fontWeight, fontSize, lineHeight, letterSpacing, textTransform }`; `responsive` (`{ "768": {...}, "1280": {...} }`); `license` |
| `spacing.json` | `dimension` | `scale` index, `base` |
| `radii.json` | `dimension` | `usage` |
| `shadows.json` | `shadow` | `$value` as CSS string or array of `{ offsetX, offsetY, blur, spread, color, inset }` |
| `motion.json` | `duration` / `cubicBezier` / `transition` / `spring` | `spring`: `{ stiffness, damping, mass }`; `transition`: `{ duration, delay, timingFunction, properties }`; `library` |
| `layout.json` | `dimension` / `number` / `object` | breakpoints, containers, grid (`{ columns, gutter, margin }`), aspect ratios |

## Naming

1. **Reuse the project's existing names** (`--color-ink`, Tailwind `brand.500`, shadcn `primary`/`muted-foreground`). Agents will map back to code more reliably.
2. If the project has no names, use `category-role-variant`: `color-accent`, `color-surface-raised`, `space-6`, `radius-card`, `duration-base`, `ease-out-expo`.
3. One name per value per theme. No duplicate definitions of the same token across files.

## `colors.css`

Mirror `colors.json` as CSS custom properties so it can be dropped into HTML templates:

```css
/* Generated by brand-extractor. Observed/Inferred tokens only. */
:root {
  --color-accent: #0A84FF;      /* observed: globals.css:12 */
  --color-bg: #FFFFFF;
}
[data-theme="dark"], .dark {
  --color-accent: #409CFF;
  --color-bg: #0A0A0A;
}
```

Use the project's own theme selector. Don't put recommended tokens in `colors.css` unless in a clearly commented separate block.

## Optional extra

If useful, also emit `brand/tokens/tokens.css` aggregating spacing, radii, shadows, fonts and motion as custom properties for HTML templates. Keep it generated from the JSON values — no new values.
